# Vertical Management

Avo Assure uses Role-Based Access Control (RBAC) to make sure every user gets the right level of access when working with it. This enables **Vertical Management** for the administrators allowing them to choose and assign roles to the users in an instance so they only see and do what’s needed for their work.&#x20;

&#x20;It improves security, avoids mistakes, and makes it easier for teams to work together, even across different domains without worrying about access and visibility to each and every Avo Assure component, not specific to their role or task.

### The benefits of **Vertical Management** in Avo Assure:&#x20;

* **Controlled Access:** Users only see and do what their role permits&#x20;
* **Improved Security:** Prevents unauthorized changes or access&#x20;
* **Streamlined Collaboration:** Roles like Tester, Reviewer, Manager, or Admin make responsibilities clear&#x20;
* **Scalability:** Easy to manage permissions as teams and projects grow&#x20;

### Key Entities in Avo Assure:&#x20;

**There are three key entities in Avo Assure:**&#x20;

{% tabs %}
{% tab title="1. Users" %}
Who login and use Avo Assure and are added in Avo Assure directly or integrate to SSO
{% endtab %}

{% tab title="2. Projects" %}
An application under test or project that stores elements, testcases, execution profiles and reports&#x20;
{% endtab %}

{% tab title="3. Agents/Grids" %}
Are used for test execution in Avo Assure&#x20;
{% endtab %}
{% endtabs %}

These key entities / resources can be assigned or controlled by different vertical or users. In other words, Projects, Users and Agents / Grids in Avo Assure can be segregated at different levels in an enterprise as **Account level**, **Vertical Level** and **Project level**. This functionality is in addition to project level roles & responsibilities.&#x20;
